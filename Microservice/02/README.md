# Домашнее задание «Микросервисы: подходы»

## Задача 1: Обеспечение разработки

### Выбор: **GitLab CE/EE + GitLab Runner**

**Обоснование:**
GitLab — это облачная (или self-hosted) платформа, которая закрывает все требования из коробки, без необходимости интеграции сторонних продуктов (как Jenkins + GitHub + Docker Hub и т.д.).

### Как решение закрывает требования:

| Требование | Реализация в GitLab |
|------------|---------------------|
| **Облачная система** | Может быть развернута как SaaS (gitlab.com) или как частное облако (self-managed) |
| **Система контроля версий Git** | Встроенный Git-репозиторий |
| **Репозиторий на каждый сервис** | Создание отдельного Git-репозитория под каждый микросервис |
| **Запуск сборки по событию** | Триггеры `.gitlab-ci.yml` (push, merge request, tag, webhook) |
| **Запуск сборки по кнопке с параметрами** | Pipeline Schedules + Environment Variables + Manual Jobs |
| **Привязать настройки к каждой сборке** | CI/CD Variables, Environments, Rules |
| **Шаблоны для различных конфигураций** | CI/CD Templates, Reusable snippets, include-механизм |
| **Безопасное хранение секретов** | Protected Variables, Masked Variables, Vault Integration |
| **Несколько конфигураций из одного репозитория** | Multiple pipeline triggers, Environment-specific pipelines |
| **Кастомные шаги при сборке** | Custom Scripts, `script:`, `before_script:`, `after_script:` |
| **Собственные докер-образы** | Registry (Container Registry) + Custom Docker Images в `image:` |
| **Агенты сборки на своих серверах** | GitLab Runner (self-managed) — ставится на любой Linux/Windows/Mac |
| **Параллельный запуск сборок** | Concurrent pipelines, parallel jobs |
| **Параллельный запуск тестов** | Распараллеливание тестов через `parallel:` или сплит по индексам |

### Итог:
GitLab — единое решение, которое покрывает весь цикл разработки: от хранения кода до CI/CD, управления артефактами и секретами. Экономит время на интеграцию и поддержку.

## Задача 2: Логи

### Выбор: **Loki + Promtail + Grafana**

**Обоснование:**
Стек от Grafana Labs, нативно интегрирован с Grafana (единый UI для логов и метрик), легковесный, в отличие от ELK (Elasticsearch + Logstash + Kibana) не требует огромных ресурсов.

### Как решение закрывает требования:

| Требование | Реализация |
|------------|------------|
| **Сбор логов со всех хостов** | Promtail ставится на каждый хост (DaemonSet) и шлёт логи в Loki |
| **Сбор логов из stdout** | Promtail автоматически собирает логи из stdout контейнеров Docker/K8s |
| **Гарантированная доставка** | Loki принимает логи через push API, Promtail поддерживает retry и кэширование на диске |
| **Поиск и фильтрация** | LogQL (аналог PromQL) — мощный язык запросов по логам |
| **Пользовательский интерфейс** | Grafana UI, права доступа на уровне организаций/команд |
| **Ссылка на сохранённый поиск** | Share Dashboard / Link to Query (прямая ссылка на запрос в Grafana) |

### Итог:
Loki — дешёвый и быстрый аналог ELK. Он не индексирует всё подряд (как Elasticsearch), а использует лейблы и сжатие. Идеален для микросервисов и Kubernetes.

## Задача 3: Мониторинг

### Выбор: **Prometheus + Grafana + Node Exporter + cAdvisor**

**Обоснование:**
Прометей — стандарт де-факто для мониторинга в микросервисной архитектуре и Kubernetes. Нативная поддержка pull-модели, огромная экосистема экспортеров.

### Как решение закрывает требования:

| Требование | Реализация |
|------------|------------|
| **Сбор метрик со всех хостов** | Node Exporter на каждом хосте отдаёт метрики Prometheus'у |
| **Метрики CPU, RAM, HDD, Network** | Node Exporter предоставляет все эти метрики |
| **Метрики ресурсов для каждого сервиса** | cAdvisor (встроен в Docker) + Service Discovery в Prometheus |
| **Специфичные метрики для сервисов** | Custom Exporters (например, для Java — JMX Exporter, для Python — Prometheus Client) |
| **UI с запросами и агрегацией** | Grafana + PromQL (запросы, агрегация, фильтрация) |
| **UI с панелями для отслеживания** | Grafana Dashboards (создание и настройка панелей) |

### Итог:
Prometheus — это стандарт для мониторинга в микросервисах. Он лёгкий, горизонтально масштабируется (через Federation), имеет богатый язык запросов (PromQL) и идеально интегрируется с Grafana для визуализации.
