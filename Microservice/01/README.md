# Домашнее задание «Микросервисы: принципы»

## Задача 1: API Gateway

### Сравнительная таблица решений

| Возможности | **Kong** | **NGINX** | **Traefik** | **Envoy** | **APISIX** |
|------------|----------|-----------|-------------|-----------|------------|
| **Маршрутизация на основе конфигурации** | ✅ Плагины, Admin API | ✅ Конфиг файлы, reload | ✅ Автоматически из Docker/K8s | ✅ xDS протокол | ✅ Admin API, etcd |
| **Проверка аутентификации** | ✅ JWT, OAuth2, Key Auth | ✅ auth_request | ✅ ForwardAuth | ✅ External Authorization | ✅ JWT, Key Auth |
| **Терминация HTTPS** | ✅ Нативная | ✅ Нативная | ✅ Нативная + ACME | ✅ Нативная | ✅ Нативная |
| **Сложность настройки** | Средняя | Низкая | Низкая | Высокая | Средняя |
| **Динамическая конфигурация** | ✅ Admin API, без перезагрузки | ⚠️ Требуется reload | ✅ Автоматически | ✅ xDS | ✅ Admin API |

### Выбор: **Kong Gateway**

**Обоснование:**
- Имеет встроенный JWT плагин для проверки токенов.
- Нативная терминация HTTPS с поддержкой Let's Encrypt.
- Динамическое управление маршрутами через Admin API без перезагрузки.
- Построен на NGINX/OpenResty — проверенная производительность.
- Активное сообщество и хорошая документация.

## Задача 2: Брокер сообщений

### Сравнительная таблица решений

| Возможности | **Apache Kafka** | **RabbitMQ** | **NATS** | **Redis Pub/Sub** |
|------------|------------------|--------------|----------|-------------------|
| **Кластеризация** | ✅ Распределенный | ✅ Federation, Clustering | ✅ Clustering | ⚠️ Sentinel |
| **Хранение на диске** | ✅ Всегда | ✅ Persistence | ✅ JetStream | ❌ В памяти |
| **Скорость** | Очень высокая | Средняя-высокая | Очень высокая | Высокая |
| **Форматы сообщений** | Любые бинарные, Avro, JSON | Любые, AMQP | Текстовые, бинарные | Текстовые, бинарные |
| **Разделение прав доступа** | ✅ ACL, SASL, RBAC | ✅ Пользователи, права | ✅ Accounts, JWT | ⚠️ Ограниченно |
| **Простота эксплуатации** | Сложная (Zookeeper) | Средняя | Простая | Очень простая |

### Выбор: **RabbitMQ**

**Обоснование:**
- Отличная встроенная поддержка кластеризации с репликацией.
- Гарантированное хранение сообщений на диске.
- Развитая система прав доступа (пользователи, роли, vhost).
- Достаточная производительность для большинства задач.
- Проще в эксплуатации, чем Kafka, и не требует Zookeeper.
